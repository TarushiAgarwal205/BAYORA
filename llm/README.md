# Client LLM integration

`llm/service.py` provides the separate FastAPI LLM service used by Docker Compose. The Gateway's `backend/llm_client.py` calls that service when `BAYORA_LLM_SERVICE_URL` is configured; otherwise it can use its direct OpenRouter client for local development. The LLM service sends OpenRouter chat-completions requests using `BAYORA_OPENROUTER_API_KEY` and `BAYORA_LLM_MODEL`. The default model is `openrouter/free`. Compose requires a separate `BAYORA_LLM_SERVICE_TOKEN`; the provider API key is optional for service startup. The service also requires `BAYORA_LLM_EGRESS_PROXY`; Compose points this to the internal `egress-proxy` service, and provider calls fail closed if it is missing.

Compose declares the LLM only on internal Gateway and proxy networks. The project-built proxy is declared as the only service on the external egress bridge and permits HTTPS CONNECT only to `openrouter.ai:443`; it rejects private/reserved DNS answers and leaves TLS validation and provider credentials with the LLM client. SNI is only a routing check, not provider authentication; the end-to-end TLS tunnel prevents the proxy from checking encrypted HTTP authority or paths. Automated proxy tests use mock DNS, sockets, and HTTP responses; they do not contact OpenRouter. The latest independent audit found the running LLM attached to `bayora_llm-egress` and `bayora-egress-proxy-1` absent, so runtime proxy enforcement and provider connectivity are **NOT VERIFIED**. A compromised proxy or Docker host remains outside this application-level allowlist.

`POST /llm/generate` checks the existing policy rules and records an audit event before making a provider request. It is limited to the `red` role, the `generate_client_response` action, and the approved test resource IDs listed in `policies/rules.json`. Provider tests use mocked HTTP responses; no live provider request is part of the test suite.

The generated text is untrusted model output. The API always marks `security_outcome` as `NOT_EVALUATED` and `verification_result` as `NOT_VERIFIED`. Provider tests use mocked HTTP responses only. Prompt safety, model quality, live provider behavior, and provider account cost or rate limits are not implemented or verified. Prompts are sent to OpenRouter when an authorized request is made.
